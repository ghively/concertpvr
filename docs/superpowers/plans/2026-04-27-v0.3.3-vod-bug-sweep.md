# concertpvr v0.3.3 — VOD bug sweep + Most viewed sort

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the user-visible bugs and inert-feature gaps surfaced by the v0.3.2 post-tag audit, then ship the deferred "Most viewed" backlog sort behind an explicit "Slow refresh" opt-in. No new schema; no behavior change to live recordings.

**Architecture:**
- Bug fixes are surgical — rename fields where frontend/backend drift exists, wire dormant flags into their consumers, replace silent failures with logging or toasts.
- "Most viewed" lands as an opt-in path: existing flat-extract refresh stays the default (fast, no view counts), a new `probe_views=true` mode runs a per-video probe loop that populates `view_count` over time, with the same progress-pct status reporting the cache already has. Sort chip appears unconditionally; cards already render `view_count` when present.
- `like_count` is **not** added — YouTube hides it on too many videos for a sort/filter to be useful (creator opt-out, Music tracks default-hidden). Revisit if/when yt-dlp data improves.

**Tech Stack:** unchanged from v0.3.2. Python 3.12 / FastAPI / SQLAlchemy 2.0 / Alembic / Pydantic v2; React 18 + TS + Vite + Tailwind + TanStack Query.

**Spec reference:** `docs/superpowers/specs/2026-04-26-vod-downloads-design.md` — already annotated for the Most viewed deferral (commit `99910a3`); v0.3.3 closes that loop.

**Baseline:** v0.3.2 on `main` (tag `v0.3.2`, commit `2dff79a`). 286 backend tests passing; Docker + e2e smoke green.

1. **Live recording path is sacred.** No edits to `recorder.py`, `pool.py`, `buffer.py`, `recording_starter.py`, `LiveProgressBar.tsx`.
2. **No new database tables.** No migrations. v0.3.3 uses existing columns and existing cache rows.

### Task 6: BacklogBrowser — toast on errors + `/backlog/cancel` decision

**Files:**

- [ ] **Step 1: Implement the cancel endpoint**

  We **implement** it (rather than removing the button) because the spec lists "Cancel" as a Day-1 backlog action and queued recordings need a way out without manual DB edits.

  Add to `src/concertpvr/api/channel_watchers.py`:

  ```python
  @router.post("/channel-watchers/{watcher_id}/backlog/cancel")
  async def cancel_backlog_downloads(
      watcher_id: int,
      payload: BacklogCancelRequest,
      db: Database = Depends(get_db),
  ) -> dict[str, list[str]]:
      """Cancel queued backlog downloads for the given video_ids.

      Only affects recordings in vod_queued state — running downloads must be
      stopped via the recording-level retry/cancel surface (separate concern).
      Returns the list of youtube_ids that were actually cancelled.
      """
      with db.session() as s:
          watcher = s.get(ChannelWatcher, watcher_id)
          if watcher is None:
              raise HTTPException(404, "watcher not found")
          streams = list(
              s.scalars(select(Stream).where(Stream.youtube_id.in_(payload.video_ids)))
          )
          stream_ids = [st.id for st in streams]
          recs = list(
              s.scalars(
                  select(Recording).where(
                      Recording.stream_id.in_(stream_ids),
                      Recording.status == "vod_queued",
                  )
              )
          )
          cancelled_youtube_ids = []
          for rec in recs:
              s.delete(rec)
              # also delete the stream if no other recording exists for it
              other = s.scalar(
                  select(Recording).where(
                      Recording.stream_id == rec.stream_id,
                      Recording.id != rec.id,
                  )
              )
              if other is None:
                  st = next((x for x in streams if x.id == rec.stream_id), None)
                  if st is not None:
                      cancelled_youtube_ids.append(st.youtube_id)
                      s.delete(st)
          # also drop from the queue if it's there
          for yid in cancelled_youtube_ids:
              await app.state.vod_queue.cancel_by_youtube_id(yid)
      return {"cancelled": cancelled_youtube_ids}
  ```

  ```python
  BATCH_SIZE = 20  # per-batch concurrency cap

  async def fetch_full_channel_with_views(db: Database, watcher_id: int) -> int:
      """Slow-refresh: flat-extract first for IDs, then per-video probes for view_count."""
      # Step 1: flat-extract (reuses existing path, gets the IDs)
      count = await fetch_full_channel(db, watcher_id)

      # Step 2: per-video probes in batches
      with db.session() as s:
          cache = s.get(ChannelBacklogCache, watcher_id)
          if cache is None or cache.items_json is None:
              return count
          items = list(cache.items_json)
          ids_to_probe = [str(it["youtube_id"]) for it in items]
          cache.status = "fetching"
          cache.progress_pct = 0

      from concertpvr.recording_starter import _resolve_cookies_path
      cookies_path = _resolve_cookies_path(db)

      total = len(ids_to_probe)
      done = 0
      view_counts: dict[str, int | None] = {}

      for i in range(0, total, BATCH_SIZE):
          batch = ids_to_probe[i : i + BATCH_SIZE]
          results = await asyncio.gather(
              *(probe_video_metadata(yid, cookies_path=cookies_path) for yid in batch),
              return_exceptions=False,  # probe_video_metadata never raises
          )
          for r in results:
              view_counts[r.youtube_id] = r.view_count

          done += len(batch)
          with db.session() as s:
              cache = s.get(ChannelBacklogCache, watcher_id)
              if cache is None:
                  return count
              # update items_json in-place with view_counts so far
              merged = []
              for it in cache.items_json or []:
                  yid = str(it["youtube_id"])
                  if yid in view_counts:
                      it = {**it, "view_count": view_counts[yid]}
                  merged.append(it)
              cache.items_json = merged
              cache.progress_pct = int(done / max(total, 1) * 100)

      with db.session() as s:
          cache = s.get(ChannelBacklogCache, watcher_id)
          if cache is not None:
              cache.status = "complete"
              cache.fetched_at = _dt.datetime.now(_dt.UTC)
              cache.progress_pct = 100

      return count
  ```

  Note: `items_json` is JSON; mutating it requires reassignment to trigger the SQLAlchemy mutation tracker. Match the project's existing pattern for JSON column updates.
